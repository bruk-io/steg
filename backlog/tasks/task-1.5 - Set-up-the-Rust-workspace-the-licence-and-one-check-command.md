The frame everything else lands in: crates for the kernel, for the server and CLI binary, and for the app. R59 (MIT), R61 (the server and CLI are one binary), R58 (no telemetry, no network call the user did not ask for).

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Files that change

Root (new):
- Cargo.toml - virtual workspace manifest. `resolver = "3"` (a virtual manifest does not inherit the resolver from `edition = "2024"`, so this is required, not decorative). `members = ["crates/kernel", "crates/server", "crates/cli", "crates/steg", "crates/app"]`. `[workspace.package]`: edition = "2024", license = "MIT", version = "0.1.0". `[workspace.dependencies]`: `gpui = { version = "=0.2.2" }` (pinned exact version - AC#4 - kept at the workspace level so cargo-deny's `[bans.workspace-dependencies] duplicates` default of "deny" has one declaration to point at, not a direct dependency buried in one crate). `[workspace.lints.clippy]`: unwrap_used, missing_errors_doc, missing_panics_doc, undocumented_unsafe_blocks, wildcard_enum_match_arm, allow_attributes_without_reason, await_holding_lock all set to "deny" directly - AC#11 says the workspace's lints are "warnings as errors" in `[workspace.lints]` itself, so the table is where that lives, not only the `lint` recipe's `-D warnings` flag (that flag still matters for the many lints this table does not name).
- LICENSE - plain MIT text, copyright line matching the identity already used in this repository's commits (R59).
- rust-toolchain.toml - channel "1.98.1" (the machine's installed toolchain), components ["rustfmt", "clippy"], so the 2024-edition toolchain is pinned, not assumed.
- deny.toml - `[licenses] allow = [...]` seeded with the permissive licenses already known to appear in gpui's dependency tree (MIT, Apache-2.0, Apache-2.0 WITH LLVM-exception, BSD-2-Clause, BSD-3-Clause, ISC, Unicode-3.0, Zlib), expanded only with more permissive licenses once the real lockfile shows what's actually there. `[bans] deny = [...]` naming tokio, async-std, mio and socket2 with `wrappers = ["steg-server", "steg", "steg-app", "steg-cli"]` and a reason citing architecture.md - the concrete start of the kernel/server I/O boundary check (AC#6; see the named decision below on whether this is the whole mechanism).
- Cargo.lock - generated by the first `cargo build --workspace`, committed (this ships binaries).

Five new crates, each a thin frame (no behaviour - that is TASK-1.6 onward). Every crate manifest sets `edition.workspace = true` and `license.workspace = true` explicitly (AC#3 depends on that inheritance actually being wired on each crate, not just declared once at the workspace):
- crates/kernel (package steg-kernel, lib): `#![forbid(unsafe_code)]` in src/lib.rs, `[lints] workspace = true`, no dependencies.
- crates/server (package steg-server, lib): depends on steg-kernel via `path = "../kernel"`.
- crates/cli (package steg-cli, lib): no dependencies yet (the wire protocol and CLI design are open spikes - TASK-1.2, TASK-1.4).
- crates/steg (package steg, bin): depends on steg-server and steg-cli via path. This is the single binary that satisfies AC#2/R61 (see the named decision below on this versus folding the binary into steg-cli). main.rs is a placeholder that does nothing yet.
- crates/app (package steg-app, bin): `gpui.workspace = true`. main.rs is a placeholder, kept to whatever is the smallest real call into gpui that proves the pin compiles and links (decided once gpui 0.2.2's actual exported API is read from docs.rs/source, not from memory, since GPUI is pre-1.0 and may have changed).

tools/ (existing package, no pyproject change expected - testpaths already covers the whole tree):
- tools/src/steg_tools/affected.py - fixed wherever real `cargo metadata` output disagrees with the assumptions the made-up-fixture unit tests encoded (AC#8's whole point). Specific shape to watch: the `path` key's presence and format on dependency entries, and how `manifest_path` resolves relative to the repo root for each of the five real crates.
- tools/tests/adapter/test_affected_real_workspace.py (new) - runs real `cargo metadata --no-deps --format-version 1` against this repository's own workspace once it exists, feeds the JSON into `crates_from_metadata`, and asserts the five real crates and their real dependency edges (kernel -> server -> steg; cli -> steg; app standalone) come back correctly - the adapter proof AC#8 asks for, replacing "tested only against made-up crates." A second case feeds the same real crate tuple through `selection()` with synthetic changed-file lists (e.g. "crates/kernel/src/lib.rs" alone, "crates/app/src/main.rs" alone) and checks the expected `-p` sets - this is the part of the proof that doesn't depend on this branch's own diff (see point 1 under Risks).
- tools/tests/unit/test_affected.py - left as is unless a real fix to affected.py changes its contract; its made-up fixtures still prove the pure logic in isolation.

justfile (existing, edited):
- `deny` recipe's command becomes `cargo deny check licenses bans` (today it only runs `licenses`; `bans` is where the boundary check in AC#6 lives). If `cargo-deny` is missing, the command fails and `{{quiet}}` prints the failure and the log path as it already does for any other failing step - the log will show "command not found," which is enough to point someone at `just setup`. `check` is deliberately *not* given `setup` as a prerequisite: that would make the verification command install software as a side effect, and in CI (TASK-1.23) that is "build cargo-deny from source on every check run."
- Add a `setup` recipe: checks `command -v cargo-deny`, and if absent runs `cargo install cargo-deny --locked` through `{{quiet}}`. Cargo-deny first and the only thing needed right now; safe to run again because it short-circuits when already installed.
No other justfile recipe needs to change for this task's acceptance criteria: `test`/`test-all`/`fmt`/`fmt-check`/`lint`/`build`/`affected` already do real work once `Cargo.toml` exists and already print one line through `{{quiet}}` on success (AC#9). `run` is a named exception - see the decision below.

Order of work

1. Write the root Cargo.toml, LICENSE, rust-toolchain.toml and the five crates' Cargo.toml/src files (no deny.toml yet - cargo-deny needs a resolvable lockfile to check against).
2. `cargo build --workspace` for the first time. This is where gpui actually resolves and compiles (the slow, risky step - see Risks). Fix whatever the real GPUI 0.2.2 API disagrees with in app's placeholder main.rs. Commit the resulting Cargo.lock.
3. Install cargo-deny (`cargo install cargo-deny --locked`), write deny.toml, run `cargo deny check licenses bans` by hand and widen the `[licenses] allow` list to whatever permissive licenses the real graph actually has - stop and raise on the task rather than widen it if anything GPL/AGPL turns up.
4. Prove AC#5 and AC#6 are real refusals, not configuration nobody exercises:
   - AC#5: temporarily remove "MIT" from `[licenses] allow`, run `cargo deny check licenses`, confirm it fails naming the MIT-licensed crates it now refuses, then restore it.
   - AC#6: temporarily add `tokio = "1"` as a direct dependency of crates/kernel/Cargo.toml, run `cargo deny check bans`, confirm it fails naming steg-kernel and tokio, then revert.
   Both probes are recorded as evidence on the task; neither survives into the committed diff.
5. Write the justfile's `setup` recipe and the `deny` recipe edit described above.
6. `cargo fmt --all` once over the new files, then iterate `just check` until `fmt-check`, `lint`, `deny`, `test`, `test-tools` all pass for real.
7. Fix `steg_tools.affected.py` against the real `cargo metadata` output and write `tools/tests/adapter/test_affected_real_workspace.py` (AC#8). Run `just test-tools`.
8. Commit everything so far. Then prove `just test`'s selection against the real workspace with a genuinely isolated diff: this branch's own diff against `origin/main` touches `Cargo.toml`/`Cargo.lock`/`justfile`/`tools/`, all of which `steg-affected` already treats as global, so it cannot show per-crate selection from the branch diff itself. Instead run `uv run --quiet --project tools steg-affected --base HEAD` (empty `since`, so only an uncommitted touch counts) after touching crates/kernel/src/lib.rs alone, and again after touching crates/app/src/main.rs alone, and confirm the two cases select different, correct `-p` sets; then discard those probe touches.
9. Run `just test-all`, `just fmt`, `just fmt-check`, `just lint`, `just deny`, `just build`, `just setup` (twice, to show it is safe to run again) individually (AC#7, AC#10). Attempt `just run` under a timeout, reporting plainly whether a window was actually observed to open in this environment or only that the process started without crashing.
10. Final `just check`, review the full diff, commit.

Risks

- GPUI is pre-1.0 and changed how it's published since anything remembered about it: it is now a standalone crate on crates.io (0.2.2, Apache-2.0, edition 2024), not a git dependency into the zed monorepo as older memory would assume - confirmed directly against the crates.io API and its real dependency list before writing this plan, rather than assumed. Its wayland/x11 default features are gated to `cfg(target_os = "linux"/"freebsd")` in its own manifest, so they should not build on macOS, but that is confirmed for real only once `cargo build --workspace` runs.
- `steg-affected`'s own global-file list (Cargo.toml, Cargo.lock, justfile, tools/) means this task's branch diff will always select "all." The real per-crate proof for AC#8 has to use `--base HEAD` against an isolated, later touch (step 8), not the branch's own history - easy to get wrong by just running `just test` once and declaring it proven.
- cargo-deny is not installed on this machine; `just setup` builds it from source via `cargo install --locked`, which takes a few minutes the first time. Homebrew has a bottled formula that would be faster, but assumes Homebrew is present on whatever machine runs `just setup` (dev or CI); `cargo install` needs nothing beyond the Rust toolchain this task already requires, so it is the safer default. Worth revisiting once TASK-1.23 wires CI, if the build-from-source time proves a problem there.
- "Anything that does I/O" cannot be banned exhaustively by crate name (see the named decision below). The deny.toml starter list (tokio, async-std, mio, socket2) covers the concrete sockets/async primitives architecture.md names; later tasks that add the server's real socket and pty code (TASK-1.8, TASK-1.9) will need to extend this list as real dependencies land, and nothing forces anyone to remember to.
- `just run` launches a real GPUI window. This worker's environment may have no interactive window server; the proof for that one recipe may be limited to "the binary builds and starts without an immediate crash," reported honestly rather than claimed as an observed window if one can't actually be seen.
- `steg_tools.affected.crates_from_metadata` has never run against real `cargo metadata` output before this task; expect to fix small mismatches once tried for real - that is the reason AC#8 exists.

Decisions named for the engineer (plan proceeds with the first option in each; flagging the alternative rather than deciding it unilaterally)

- AC#6's mechanism. A deny.toml crate-name denylist (as planned) needs editing every time a later task adds a real transport dependency, and can't see "the kernel added a crate that does I/O" in general - only the handful of names someone remembered to list. The alternative is a small check in tools/ that reuses `crates_from_metadata`'s own dependency-edge data (already computed for steg-affected) and asserts steg-kernel's dependency set against an explicit allow-table of workspace crates - closer to architecture.md's "enforce it with import rules," and one that keeps holding as TASK-1.8/1.9 add the pty and the socket, with no deny.toml edit required. This plan builds the deny.toml version because it is cheap and already proven in step 4; the tools/ version is a reasonable escalation if the engineer wants the boundary to self-maintain.
- `run` and the AC#9 "one line" contract. `run` currently calls `cargo run --package steg-app` directly, not through `{{quiet}}`, so it will not print the pass/fail-plus-log-path line AC#9 describes. Wrapping it in `{{quiet}}` would buffer the GPUI window's own stdout/stderr until the process exits, which is wrong for a long-running interactive foreground app. This plan leaves `run` unwrapped and treats it as exempt from AC#9 as an interactive recipe, rather than silently calling it "unchanged."
- Five crates versus the spec's four parts (kernel, server, CLI, app in section 7). This plan adds a fifth `steg` bin crate purely to carry R61 (server and CLI as one binary) without the CLI crate also being a binary target. The more literal reading of section 7 would make steg-cli itself the binary, embedding steg-server as a library dependency, with no separate `steg` crate. This plan uses the fifth crate because it keeps steg-cli a plain library other things (a future Python client, tests) can link without pulling in a `main`, but it is a frame decision every later CLI/server task inherits either way.

Proof per acceptance criterion

#2 `cargo build --workspace` produces one `steg` binary that is `steg-server` plus `steg-cli` linked together; `ls target/debug/steg` after the build.
#3 root LICENSE file, MIT text; `license = "MIT"` on `[workspace.package]`, `license.workspace = true` on every crate.
#4 `gpui = { version = "=0.2.2" }` (exact pin) in `[workspace.dependencies]`, `gpui.workspace = true` in crates/app/Cargo.toml.
#5 the MIT-removal probe in step 4: `cargo deny check licenses` fails with "MIT" removed from the allow list, and passes once restored.
#6 the kernel/tokio probe in step 4: `cargo deny check bans` fails with the temporary tokio dependency present, and passes once it is reverted.
#7 each of check/test/test-all/fmt/lint/deny/build/run individually exercised in steps 6 and 9, with real output (not the justfile's current "skip ... no Rust workspace yet" path) since `Cargo.toml` now exists.
#8 the adapter test (step 7) plus the `--base HEAD` probes in step 8, run against the real workspace, not the made-up fixtures.
#9 steg-quiet already wraps every recipe but `run` (named as an exception above); its one-line pass/fail-plus-log-path output is visible in the output of every other step above.
#10 `just setup` run twice in a row in step 9: the first time installs cargo-deny, the second time reports it already installed and does nothing else.
#11 root Cargo.toml's `[workspace.lints.clippy]` table with the seven named lints set to "deny" directly, and `edition = "2024"`; `#![forbid(unsafe_code)]` in crates/kernel/src/lib.rs; building any crate that violates one of the seven lints fails without needing the `lint` recipe's `-D warnings` flag, which is evidence the table itself enforces them.

- The three named decisions above (AC#6's mechanism, `run`'s exemption from AC#9, and the fifth `steg` crate versus folding the binary into steg-cli).
